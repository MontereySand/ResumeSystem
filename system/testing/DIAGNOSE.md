# Requested setup diagnosis

Optional, read-only, selected by `resumeguide` when the user asks to check setup. Not a mandatory intake checklist and not permission to install, repair, build, save notes, export, change settings/trust or use Git. Reuse unchanged findings already in context. Root `AGENTS.md`, `system/agent/core.md` and `system/agent/rendering.md` define the behavior.

1. For the selected fault, identify only the relevant actual OS, personal root, `main/main.tex` or selected application source, editor/profile/extension host and agent capabilities. Do not inspect unrelated profiles/apps or every application.
2. Check only instructions and actual imports required for that operation, selected TeX source/style and relevant `.vscode/` entries. Distinguish absent, unreadable, symlink/redirect and occupied paths. Presence is not integrity/overwrite permission; damaged personal state is not a reset signal.
3. Discover current `pdflatex`, `latexmk`, `kpsewhich`, optional `chktex` and needed Perl with existing native command discovery/known installation locations. Nonwriting version checks are sufficient for diagnosis. Reuse current MacTeX; `/Library/TeX/texbin` is the stable Mac entry, not Strawberry Perl. Windows TeX Live/MiKTeX and conditional Strawberry follow rendering.md. Do not repeat an unchanged known failure.
4. Check James Yu LaTeX Workshop in the actual editor/profile, selected recipe command/child PATH and selected `system/build/` output location (rendering.md). Preserve Mathematic/other saved-PDF viewers; none compiles TeX. A terminal PATH, installed extension or successful version check is not a preview/build pass. ChkTeX absence is only a lint limit; no formatter/runtime is required.
5. Read existing relevant logs/output only if needed and authorized. State which tool/engine, actual file/dependency or permission blocks the selected operation. A fresh build, generated inspection images or GUI actions need the distinct authorized scope; a read-only diagnosis creates nothing.
6. Return exact findings and one useful next step. Missing dependency uses rendering.md's named official-install/permission handoff; missing owned program file uses updates.md's scoped compatible-source repair; personalized source/data need their actual backup. Do not run repair as a diagnosis side effect or disguise a failure by disabling a linter/cleaning output.

Identify warning ownership: optional Mathematic LaTeX uses `latex.linter.path`, separately from Workshop's `latex-workshop.linting.chktex.exec.path`; both can use the existing binary without installation. Workshop's `vscode-pdf` conflict warning targets `tomoki1207.pdf`, not Mathematic PDF. Diagnose exact enabled IDs and propose a workspace-only duplicate-viewer disable with explicit consent; never change extension state during read-only diagnosis or hide the warning.

For requested native commands, identify the actual host and follow updates.md for the twelve names plus the repair alias; file existence is not native menu discovery. Git availability/history is diagnosed only with its separate permission and every git.md guard; no-Git means zero Git invocations.
